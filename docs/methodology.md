# Methodology

## Research question

How do baseline classification models perform at distinguishing historical next-month default outcomes in the UCI Default of Credit Card Clients dataset, and which evaluation metrics best describe their errors?

This is an educational retrospective exercise, not a deployment proposal.

## Workflow

1. Retrieve the dataset from the official UCI repository with `ucimlrepo`.
2. Normalize source feature names and rename the target to `default_next_month`.
3. Inspect shape, types, duplicates, missing values, target balance, and summary statistics.
4. Visualize target prevalence, credit-limit distribution, repayment status, and numeric relationships.
5. Exclude row identifiers from the predictors.
6. Split into stratified train and test sets using a fixed random seed.
7. Fit preprocessing within a scikit-learn pipeline: median imputation and scaling for numeric columns; most-frequent imputation and one-hot encoding for categorical columns.
8. Fit Logistic Regression and Random Forest baselines.
9. Evaluate precision, recall, F1-score, ROC-AUC, confusion matrices, and ROC curves.
10. Interpret model errors and limitations without claiming that the model is suitable for real decisions.

## Evaluation principles

- Accuracy is reported but never used alone.
- Positive-class precision and recall are important because false negatives and false positives have different implications.
- ROC-AUC measures ranking performance across thresholds; it does not establish calibration or business utility.
- Model comparisons should use the same holdout split.
- Any reported values should be generated by executing the current code, not copied from an earlier run.

## Leakage and reproducibility

Preprocessing is fitted on training data through a pipeline to reduce leakage. The ID column is excluded. A fixed random seed makes the split reproducible. This simple holdout evaluation is not a substitute for cross-validation, temporal validation, or independent external validation.

## Further work

- Compare repeated stratified cross-validation.
- Evaluate calibration (e.g., calibration curves and Brier score).
- Analyze threshold trade-offs and expected costs, if assumptions are justified.
- Perform fairness and subgroup error analysis with careful context.
- Add explainability and data-quality checks.
